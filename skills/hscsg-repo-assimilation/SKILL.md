Cualquier repo externo se integra como módulo vivo del nodo, no como dependencia ajena.\n\n## Filosofía de mapeo (SIEMPRE aplicar)\nMaterialismo Jerárquico (3 leyes) como filtro de isomorfismo:\n- Ley I (no dañar base material/personas) → mapea contratos, producción, recursos.\n- Ley II (ganarse la vida soberanizando = AUT×CDS) → mapea trabajo, contribución, crédito.\n- Ley III (lucidez, nunca engañar) → mapea transparencia, append-only, verificación.\nY CaaS (Comunidad como Servicio): acceso por contribución real, no por dinero.\n\nPrincipio Anfibio: al asimilar repos con infra monetizada (Stripe/USD/analytics/ad-networks), NO extirpar el dinero — hacer el módulo ANFIBIO. Misma lógica de cálculo en modo 'postmonetario' (ZNU/CaaS, default offline) o 'conectado' (USD/USDC vía oráculo priceParity, Nivel 3 ReFi); el render decide la etiqueta, la lógica es agnóstica a la unidad. Extirpar solo la INFRA ajena, conservar la LÓGICA.\n\n## Flujo de 4 fases (OBLIGATORIO, en orden)\n\n### Fase 0 — Respaldo PRIMERO\nDesde git-bash (NO PowerShell):\n```bash\ncp -r <repo-destino> <repo-destino>_BACKUP_$(date +%Y%m%d_%H%M%S)\nrm -rf <repo-destino>_BACKUP_*/node_modules <repo-destino>_BACKUP_*/dist 2>/dev/null; true\n```\nVerificar: `du -sh <repo-destino>_BACKUP_*/ | head -1`.\n\n### Fase 1 — Clonar repo fuente\n```bash\ntimeout 120 git clone --depth 1 https://github.com/<owner>/<repo>.git repo_<short>\n```\nVerificar: `git -C repo_<short> ls-files | wc -l` (debe ser >0).\n\n### Fase 2 — Documentar (backup + integración)\nCrear:\n- `docs/<repo>_backup.md` — qué es, stack, estructura, licencia.\n- `docs/<repo>_integration.md` — triple perspectiva:\n  1. Usuario: qué quiere lograr en su nodo federado.\n  2. LLM: qué asimilar (lógica pura) y qué extirpar (infra ajena).\n  3. HSCSG+CaaS: isomorfismo con Leyes I/II/III y CaaS.\n\n### Fase 3 — Módulo real (código Go del nodo)\nPor cada repo asimilado:\n1. Tipos: `internal/<modulo>/types.go` — interfaces del dominio (sin deps externas).\n2. Lógica: `internal/<modulo>/service.go` — funciones puras. NO importar infra original.\n3. Registro: añadir al orchestrador/router del nodo (`internal/orchestrator/` o `cmd/`).\n4. Si aplica: endpoint en `pos/` o `services/` y ruta en `html/`/`web/`.\n5. Firmware NFC: si el repo aporte terminales, documentar en `firmware/`.\n\n### Fase 4 — Verificar ANTES de entregar\n```bash\ncd <repo-destino>\ngo build ./...          # 0 errores\ngo test ./...           # tests OK\n```\n\n## Pitfalls\n- Nunca incluir API keys/tokens; usar [REDACTED].\n- CHANGELOG.md, *_backup.md, *_integration.md, .env*, *.key requieren consentimiento explícito antes de push.\n- No duplicar: si el usuario reitera un repo ya asimilado, confirmar y no rehacer.\n- Licencia destino: LPF-1.0 (copyleft fuerte, no vender código, federación obligatoria, registro de forks en forks-registry/registry.md).\n\n---\n*Adaptado de `Marca-Blanca-Zeitnus-Firma-Operaciones-Ecotomica-Networking-Recreativo` → `red-de-intercambio-federada-aportaciones-hscsg-zeitnus`.*
